# Architecture frontend (web/)

Application React 19 + TypeScript construite par Vite, stylée avec Tailwind 4, état géré par Zustand. Elle tourne dans la WebView2 unique de l'hôte et porte toute l'interface : arborescence des workspaces, onglets, splits, terminaux xterm.js, Leader et palette.

## Structure

| Dossier | Rôle |
| --- | --- |
| `src/model/` | Modèle de session pur (types, fabriques, helpers d'arbre `panesOf`, `replaceNode`, `pruneNode`, `splitLeaf`, `setRatioAt` (chemin `SplitPath` de côtés `SplitSide`, ratio borné par `clampRatio`), sélecteurs `activeWorkspace`, `activeTab`, `activePane`). Aucune dépendance React ni DOM. |
| `src/store/` | Stores Zustand : `sessionStore` (session et toutes ses mutations), `hostStore` (connexion, shells, message de statut, état Leader, liste des projets et contextes Git par pane reçus de l'hôte), `paneStore` (état local d'un pane : shell qui a échoué au démarrage, shell terminé ou dossier disparu avec son repli ; un dossier disparu ignoré par l'utilisateur n'est plus signalé pour ce pane ; jamais persisté), `uiStore` (état d'édition transitoire, comme le workspace ou l'onglet en cours de renommage ou l'ouverture de la palette, jamais persisté). |
| `src/bridge/` | `messages.ts` (types des messages, miroir du contrat C#), `bridge.ts` (envoi et abonnement via `window.chrome.webview`). |
| `src/terminal/` | `terminalRegistry` (une instance xterm.js par pane, conservée hors React pour survivre aux changements d'onglet ; renderer WebGL, repli canvas puis DOM ; acquittements de flux ; `snapshot` sérialise le texte d'un pane via `@xterm/addon-serialize`, `prime` réinjecte ce texte suivi d'un séparateur avant de lancer un nouveau processus), `tabLifecycle` (fermeture d'un onglet, d'un pane ou d'un workspace entier avec capture du texte, réouverture du dernier onglet fermé), `contextActions` (actions sur le dossier réel du pane : copier le chemin, ouvrir dans l'éditeur ou l'explorateur via `context.open`, copier la branche après `context.query` ; `gitSummary` produit « Aucun dépôt Git », « HEAD détachée », « Aucune branche » ou « Branche : x », jamais de valeur fictive), `paneLifecycle` (relance du shell d'un pane, relance dans un dossier de repli, changement de shell puis relance, ou abandon du signalement ; `terminalRegistry.restart` renvoie `terminal.create` sur la même instance xterm.js, le texte précédent reste visible), `TerminalPane` (composant qui attache l'instance à son élément). |
| `src/palette/` | `searchFilter.ts` (type `SearchItem` et filtrage par mots, insensible à la casse et aux accents, partagé par la palette et le sélecteur de projets), `paletteItems.ts` : construit la liste de la palette (commandes avec leur raccourci, nouvel onglet par shell disponible, renommages qui ouvrent les éditeurs inline, déplacement de l'onglet vers un autre workspace, puis navigation vers chaque workspace, onglet et pane) et la filtre par mots sans tenir compte des accents ni de la casse. Les commandes marquées favorites (`session.favorites`, identifiants stables des commandes) sont placées en tête de liste. Aucune dépendance React. |
| `src/keyboard/` | `shortcuts.ts` : enum `Command` et une seule fonction `runCommand`, déclenchée soit par le Leader Ctrl + Espace (5 s) puis lettre, soit par un raccourci direct Ctrl + Maj + lettre ou Alt + flèche (tableau en section 9 de la spec). Les flèches (directes ou après Leader) changent de pane de façon spatiale via `paneNavigation`. Ctrl + P (ou Ctrl + Maj + P) ouvre la palette, Ctrl + Maj + C/V copier/coller (Ctrl + C copie aussi quand une sélection existe et la désélectionne, sinon il interrompt le shell), Ctrl + Maj + PageUp/PageDown (ou Leader puis PageUp/PageDown) déplace l'onglet actif, Ctrl + Maj + Z (ou Leader puis Z) rouvre le dernier onglet fermé, Alt + F4. Tout est intercepté dans xterm.js via `attachCustomKeyEventHandler`, jamais par l'hôte. Pendant le Leader : Échap annule, une touche sans commande ou un second Ctrl + Espace rend la frappe au terminal (ce dernier permet d’envoyer Ctrl + Espace à PSReadLine), l’expiration après 5 s l’annonce dans la barre de statut. Les événements en cours de composition IME (`isComposing`) passent toujours au terminal. `LEADER_HINTS` liste les séquences affichées par `LeaderHints`. |
| `src/components/` | Un composant par fichier : `AppShell` (monte `CommandPalette` et écoute Ctrl + P au niveau du document pour l'ouvrir quand le focus n'est pas dans un terminal ; à la fermeture le focus revient au pane actif, avant qu'un éventuel éditeur inline ne le prenne), `SearchDialog` (boîte générique `role="dialog"` avec champ `combobox` et liste `listbox`, utilisée par `CommandPalette` et `ProjectPicker` : ↑ / ↓ déplacent la sélection en boucle et la gardent visible, Entrée exécute, Échap ou clic hors de la boîte ferme, la sélection revient au premier résultat à chaque frappe, liste vide affiche « Aucun résultat. » et Entrée n'exécute rien ; sélection marquée par le fond seulement ; une étoile à droite de chaque commande, ou Ctrl + Entrée sur la sélection, bascule le favori via `sessionStore.toggleFavorite`), `CommandPalette` (construit les entrées de la palette), `ProjectPicker` (Leader puis F ou entrée « Ouvrir un projet » de la palette : demande `projects.list` à l'hôte, liste les dossiers réels de `C:\Files\Projects`, Entrée crée un workspace nommé comme le dossier avec un premier terminal dedans ; racine absente affichée comme message, aucune modification du contexte courant), `Header`, `LeaderHints` (rappel des séquences Leader dans l’en-tête tant que le Leader est actif), `WorkspaceTree` (chaque workspace et chaque onglet a une croix visible au survol ou au focus ; clic molette ferme aussi un onglet ; fermer un workspace ferme ses onglets un par un, les cinq derniers restant restaurables), `TabBar`, `SplitView` (récursif : chaque branche reçoit son chemin `SplitPath` depuis la racine, dimensionne ses enfants par `flex` selon `ratio` et intercale un `SplitResizer`), `SplitResizer` (séparateur `role="separator"` entre deux sous-zones : glisser au pointeur ou flèches au clavier par pas de 5 %, ratio borné 15–85 % par le modèle, persisté sans toucher aux processus), `PaneView` (en-tête avec le chemin ciblé et des boutons compacts : copier le chemin, ouvrir dans l'éditeur, ouvrir dans l'explorateur, copier la branche Git (désactivé et infobulle « Aucun dépôt Git » / « HEAD détachée » sans branche ; le contexte est relu à chaque changement de dossier), puis split côte à côte, split haut/bas et fermeture ; les actions de dossier existent aussi dans la palette pour le pane actif ; porte `data-pane-id` pour la navigation spatiale ; superpose `PaneOverlay` quand `paneStore` signale un échec, une fin de processus ou un dossier disparu), `PaneOverlay` (message local au pane : « Relancer » et « Choisir un shell » après échec ou fin, « Relancer dans le dossier de repli » et « Ignorer » quand le dossier n'existe plus, toujours « Fermer le pane » ; aucun repli silencieux), `PaneOverlay` (message local au pane avec « Relancer », « Choisir un shell » via `ShellMenu` et « Fermer le pane » ; aucun repli silencieux), `paneNavigation.ts` (enum `Direction` et `paneInDirection` : choisit le pane dont le rectangle DOM est le plus proche dans la direction demandée, aucun changement s’il n’y en a pas), `EmptyState` (aucun workspace : création ou réouverture du dernier onglet fermé), `InlineNameEditor` (renommage inline des workspaces et des onglets, ce dernier par double-clic dans `TabBar` : Entrée ou perte de focus valide, Échap annule ; le store ignore un nom vide et un onglet renommé passe en `manual`, ce qui fige son nom face aux changements de dossier), `Tooltip` (infobulle unique montée par `AppShell` : tout élément portant `data-tip` l'affiche après 250 ms au survol ou au focus clavier, en position fixe pour ne jamais être tronquée ; ne pas utiliser `title`), `SidebarResizer` (séparateur `role="separator"` : glisser à la souris ou flèches gauche/droite au clavier, largeur bornée par le store), `tabDrag.ts` (glisser-déposer des onglets par événements pointeur et `elementFromPoint` sur les attributs `data-drop-*`, car le drag & drop HTML5 n'est pas relayé par la WebView2 ; état transitoire dans `uiStore` ; `TabBar` et `WorkspaceTree` sont sources et cibles : déposer sur un onglet insère avant lui, sur un workspace ou la barre ajoute en fin ; les instances xterm.js suivent leurs panes sans être recréées), `ActionMenu` (menu générique `role="menu"` : flèches / Début / Fin, Entrée, Échap, Tab ou clic extérieur ferment, entrées désactivables, en-tête optionnel), `ShellMenu` (`ActionMenu` des shells, ouvert par clic droit, Maj + F10 ou touche Menu sur le « + » de la barre d’onglets ; liste les shells disponibles annoncés par l’hôte, flèches / Début / Fin, Entrée, Échap, Tab ou clic extérieur). |
| `src/index.css` | Import Tailwind, police de symboles Nerd Font embarquée, tokens de la direction Dock (`--color-dock-*`, `--font-mono`), contour `:focus-visible` global en `dock-focus` pour un focus clavier visible partout. |

## Flux

1. `App` envoie `app.ready` ; l'hôte répond `app.hello` avec la session persistée (ou initiale) et les shells disponibles.
2. `sessionStore.load` charge la session ; `SplitView` rend l'arbre de l'onglet actif ; chaque `TerminalPane` demande `terminal.create` à son premier attachement.
3. Toute mutation du store produit une nouvelle session (clonage structurel, jamais de mutation en place) ; `App` la sauvegarde après 500 ms de calme via `session.save` et détruit les terminaux dont le pane n'existe plus.
4. `terminal.cwd` met à jour `pane.path` (et efface un éventuel état local du pane) ; le nom automatique de l'onglet, le contexte Git et les actions de dossier suivent ce chemin, ce qui couvre `wtr`. `terminal.pathMissing` (après `rmwt` ou au démarrage) marque le pane comme dossier disparu sans le fermer. `terminal.output` va directement à l'instance xterm.js sans passer par React.

## Règles

- Le modèle et le pont ne connaissent pas React. Les composants ne contiennent pas de logique métier : ils appellent les actions du store.
- Les handlers sont des fonctions nommées (`handleSelect`, `handleClose`), pas de lambdas inline avec logique dans le JSX.
- Enums TypeScript plutôt que types union pour les valeurs fermées (`SplitAxis`, `StatusLevel`, `Renderer`). `erasableSyntaxOnly` est désactivé pour cela.
- Couleurs via les tokens `dock-*` de `index.css`, jamais en dur dans les composants. Le thème xterm.js est centralisé dans `terminalRegistry`.
- Textes visibles en français.
- Fichiers de moins de 400 lignes, un composant exporté par fichier.

## Commandes

```
cd web
pnpm install
pnpm dev        # serveur Vite sur http://localhost:5173, à combiner avec DOCK_WEB_DEV_URL côté hôte
pnpm build      # tsc -b puis vite build vers web/dist
pnpm lint       # oxlint
```
